# 制作手順・問題点・改善案・長尺化

## 1. 推奨ツールの構成（2026年10月時点。機能と規約は着手時に要確認）

| 工程 | 推奨 | 理由 |
|---|---|---|
| 参照画像・キーフレーム | 参照画像に対応した画像生成・編集モデル（Gemini の画像生成・編集、GPT の画像生成、FLUX Kontext、Midjourney の Omni Reference など） | 同じ猫を別の構図で描き直せる |
| 映像生成（主力） | 開始フレームの画像から動画を作れるツール（Kling、Runway、Veo、Hailuo など） | 外見を最初のフレームで固定できる。文章だけから作るより、キャラクターが崩れにくい |
| 映像生成（予備） | 複数の参照画像を入力できるモード（Kling の Elements、Veo の参照画像など） | 2〜3 匹が同時に映るショット（S05–07、S18、S21） |
| 組み立て | 本リポジトリの `tools/build.py`（または DaVinci Resolve などの編集ソフト） | 尺、字幕、音を再現できる形で管理できる |

**基本の流れ**：参照画像 → ショットごとのキーフレーム画像（画像モデルで構図と外見を固定）→ キーフレームから 5 秒の動画 → `clips/Sxx.mp4` に置く → `python3 tools/build.py render`

## 2. 予想される問題点と対策

| # | 問題 | 起きやすいショット | 対策 |
|---|---|---|---|
| 1 | **ミケの柄が毎回変わる**（左右逆、パッチが増える・消える） | ミケが出る全カット | キーフレームから動画を作る方式に限定する。柄マップと照合して不合格は捨てる。映像を左右反転しない |
| 2 | 前足が人間の手・指のように変形する | S10（スマホを押さえる） | 前足を上げた状態をキーフレームにし、振り下ろす動きだけを 2〜3 秒生成する。ネガティブプロンプトに fingers を入れる。ダメなら「押さえた後の静止」＋効果音で見せる |
| 3 | 立ち上がる、二足歩行になる | S17、S20 | 「四足」をプロンプトの冒頭に置く。慌てる動きは後ずさり（1 本）と箱が倒れる（別の 1 本）に分ける |
| 4 | 口がしゃべるように動く | セリフのあるカット全般 | ネガティブに talking・lip sync を入れる。「口を閉じている」と明記する。口が動いた部分は使わない |
| 5 | スマホ画面の文字が崩れる | S09 | 画面は「無地で光る」だけにし、着信の文字は字幕のテロップで出す（設定済み） |
| 6 | 3 匹同時のカットで猫が混ざる（白と茶トラの中間の猫など） | S18、S21 | 画像の合成で 3 匹を配置したキーフレームを作り、動きは最小限に（固定カメラで、少し動くだけ） |
| 7 | 防犯カメラ風の映像が「きれいすぎ」て本物らしさが出ない | S01、S14、S16、S18 | 編集時に、彩度を下げる・ノイズ・魚眼レンズの歪み・解像度を下げてから戻す、といった処理を ffmpeg で後から足す（次の改善） |
| 8 | 映像のほうが「本物」に見えすぎて誤解を招く | 全編 | 左上のラベルを常に表示、冒頭と末尾に注記、YouTube のAI生成コンテンツ申告、概要欄にも明記。日時の表示は創作であることが分かる文脈で使う |
| 9 | 法律の問いかけが法的な助言と受け取られる | S24 | 今回は問いの提示だけ。解説編は、専門家の監修または一次資料（民法709条など）に基づいて作り、「一般的な情報であり個別の助言ではない」と表示する |
| 10 | 猫の鳴き声の合成音が不自然 | 全般 | 実録音を使う（`04_sound_design.md` を参照） |

## 3. 成功条件のチェックリスト（本番の映像がそろったら確認）

- [ ] 3 匹をそれぞれ、毛色・柄・目の色・体格で見分けられる（第三者 3 人に、音を消して見てもらう）
- [ ] 人間の体の一部（手、指、腕、服）が 1 フレームも映っていない（コマ送りで確認）
- [ ] 二足歩行、口パク、人間のような表情がない
- [ ] S10・S12・S20・S21 の「人間っぽい行動」が、猫の体のままコミカルに見える
- [ ] 音を消して字幕だけで見ても、話の流れが分かる
- [ ] ショットの間で色味・粒子感・画質の差が目立たない
- [ ] 「AI生成・創作再現」の表示が全編で見える

## 4. 10〜20分の動画へ広げる手順

1. **構成**：今回の 6 つのブロックを「章」として増やす（例：出会い → 交際 → 疑い → 発覚 → 対峙 → 解説 → 結末）。1 章あたり 1.5〜3 分。
2. **データ**：`data/shots.json` を章ごとのファイルに分ける（例：`ch01.json` など）。`build.py` にファイルを結合する処理を足すだけで、ほかの仕組みはそのまま使える。
3. **キャラクター資産**：今回の参照画像 7 カット × 3 匹をシリーズ共通の資産として固定する。新しいキャラクターは同じ仕様書の形式で追加する。
4. **ショット数の目安**：15 分なら約 250 ショット（平均 3.5 秒）。半分以上を「静止に近いカット」（見つめる、座る、固まる）にすると、品質と費用が安定する。動きの大きいカットは、各章のクライマックスだけに絞る。
5. **使い回し**：防犯カメラの定点カット（部屋、廊下、玄関）は背景を固定し、同じ構図の素材をストックして使い回す。
6. **解説パート**：法律の解説はテキストカードや図解を中心にし、生成費用を抑える。内容は専門家の確認を通す。
7. **確認作業**：上のチェックリストを章ごとに回す。不合格ショットの再生成率を記録し、次の作品の見積もりに使う。

## 5. 次にやるべき改善（優先順）

1. 参照画像（特にミケ）を作り、柄の一貫性が出せるかを最初に検証する。ここで失敗するなら、柄の単純な猫に変えることも検討する。
2. 最も難しい S10・S20 を先に試作し、ツールを選ぶ判断材料にする。
3. `build.py` に、防犯カメラ風の画質処理（ショットごとの `look` 指定）を加える。
